Abstract

Alpha Blockchain is a decentralized proof-of-work network engineered to Bitcoin's exact technical specification — SHA-256d PoW, 21,000,000-coin supply, 10-minute blocks, UTXO accounting, a full stack-machine Script engine, SegWit and Taproot — extended with a native token layer (ALP), SPV proofs, compact-block filters, PSBT, HD wallets and a complete explorer/REST API. It is designed to be permissionless, auditable and compatible with Bitcoin's well-understood security model.

1. Introduction

Bitcoin proved that a scarce, permissionless, censorship-resistant digital asset can be secured by pure cryptography and economic incentive — without any trusted party. Alpha Blockchain takes that design and rebuilds it from first principles: a clean-room, dependency-free Python implementation that mirrors Bitcoin's consensus behavior bit-for-bit, while adding the infrastructure modern applications actually need — a deterministic token layer, a block explorer, developer APIs and the plumbing for DeFi, identity, real-world assets and enterprise use.

The project has two goals:

  • Faithfulness — replicate Bitcoin's consensus-critical behavior exactly: the same header format, difficulty math, sighash algorithms, Script semantics and monetary schedule, audited against Bitcoin's real known-answer vectors.
  • Usability — expose everything developers need (RPC, REST, PSBT, descriptors, tokens, explorer) so the chain is a platform, not just a coin.

2. Consensus

Consensus is the set of rules every honest node independently enforces. Alpha implements Bitcoin's rules end-to-end:

2.1 Proof of Work

  • 80-byte block header: version(4) | prev_hash(32) | merkle_root(32) | time(4) | bits(4) | nonce(4)
  • Block valid iff SHA256d(header) ≤ target where target = bits_mantissa × 2^(8·(bits_exponent−3)) (bit-exact).
  • Merkle root uses Bitcoin's duplicate-last rule; witness commitments (BIP141) verified.

2.2 Difficulty retarget

new_target = old_target × clamp(actual_timespan / 20160, ¼, 4) (every 2016 blocks; target spacing = 10 minutes)

2.3 Timestamps

  • Median-time-past over 11 blocks (MTP) — miners can't jump the clock arbitrarily.
  • Future timestamps limited to +2 hours from network time.

2.4 Chain selection

  • Best chain = most cumulative chainwork (not longest). Reorgs disconnect & reconnect blocks with full UTXO/mempool/token undo.
  • BIP34: block height in coinbase; genesis reward unspendable (Bitcoin quirk).

Issuance converges on the same asymptote as Bitcoin: the sum of all future block rewards is a geometric series that asymptotically approaches but never reaches 21,000,000 — exactly 20,999,999.9769 ALPHA.

3.1 Community Reserve — 25%

5,250,000 ALPHA (25% of total supply) is allocated to a community reserve governed by a 3-of-5 multisig address — five founding members, any three required to spend. No single member controls the fund; it is released for ecosystem growth, listings, development and member benefit as the community decides.

The remaining 15,750,000 ALPHA (75%) enters circulation strictly through the Bitcoin-style mining schedule — fair, permissionless, earned by work.

3.2 Provable Burning

ALPHA supports verifiable coin destruction via the burnalpha RPC: coins are sent to an OP_RETURN output, which is unspendable by consensus — the same mechanism Bitcoin users employ to provably remove coins. Anyone can verify a burn on-chain; burned coins permanently reduce circulating supply.

4. Script & Contracts

A complete Bitcoin-style stack interpreter executes every standard locking script:

  • Legacy: P2PK, P2PKH, P2SH, m-of-n multisig, OP_RETURN
  • Timelocks: CLTV (BIP65), CSV (BIP112)
  • SegWit v0: P2WPKH, P2WSH, P2SH-P2WPKH (BIP141/143/144)
  • Taproot (BIP340/341/342): schnorr signatures, key-path & script-path spends, tapleaf merkle trees, control blocks, OP_CHECKSIGADD
  • Full sighash matrix: ALL/NONE/SINGLE/ANYONECANPAY across legacy, BIP143 and BIP341
  • Policy flags: STRICTENC, DERSIG, LOW_S, NULLDUMMY, NULLFAIL, CLEANSTACK, MINIMALIF, MINIMALDATA, WITNESS_PUBKEYTYPE

5. Tokens — the ALP protocol

Assets are issued on-chain via an OP_RETURN meta-protocol (Omni-style), so base consensus stays untouched while a deterministic parallel indexer tracks balances.

5.1 Operations

  • Issue — createtoken: defines name, decimals, supply. token_id = txid.
  • Send — sendtoken: move balances between addresses.
  • Mint / Burn — issuer-only supply changes.
  • Query — registry, info, balances, holders.

5.2 Semantics

  • Deterministic: every node replays OP_RETURN ops in block order → same state.
  • Reorg-safe: per-block undo journal rolls back token state.
  • Validation: invalid ops (over-balance sends, non-issuer mints) are ignored.
  • Extensible: sendopreturn lets projects embed their own data.

6. Network & Nodes

  • Wire protocol: Bitcoin-exact framing — magic, 12-byte command, sha256d checksum, 32MB cap
  • Handshake: version/verack, sendheaders, sendcmpct
  • Sync: headers-first + getblocks + inv/getdata relay
  • Compact blocks (BIP152): short-ID reconstruction from mempool
  • Bloom filters (BIP37): filterload/add/clear + filtered-block serving
  • Compact filters (BIP157/158): GCS block filters
  • addrv2 (BIP155), SOCKS5 proxy, Tor hidden service
  • Pruning (keep-N blocks) + assumeutxo snapshot sync
  • 24 message handlers covering the full message set

7. Wallet & Keys

  • Encryption: AES-256-CBC + SHA-512×25000 EVP_BytesToKey (encryptwallet/unlock/lock)
  • HD: BIP32 deterministic keys (xprv/xpub, hardened/normal, BIP39 seed)
  • Addresses: legacy, P2SH-segwit, bech32 P2WPKH, bech32m taproot
  • Signing: coin-select + change, all script types, signmessage/verifymessage
  • PSBT: BIP174 fund/sign/finalize + BIP380 descriptors

8. Security Model

  • RFC6979 deterministic nonces — no nonce reuse → no key leakage
  • Strict DER (BIP66) + low-S (BIP62) — signature malleability closed
  • Curve validation on all pubkeys; off-curve keys rejected
  • Cookie-auth RPC (bitcoind model), wallet file 0600, no eval/exec/pickle/subprocess
  • All consensus bounds enforced: MAX_MONEY, negative/zero outputs, double-spend, fee≥0, maturity
  • Pure-Python crypto — no external dependencies to attack
Limitations (honest): wallet passphrase lives in Python memory (no secure zeroing), AES is pure-Python (not timing-hardened), P2P DoS limits are basic, and coin selection is largest-first (not privacy-optimal).

9. APIs & Interoperability

  • JSON-RPC: ~65 bitcoind-compatible methods across chain/wallet/mining/tx/tokens/PSBT/descriptors/filters
  • REST: /rest/chaininfo|block|tx|headers|mempool|utxo|tokens
  • Web/explorer API: /api/stats|blocks|block|tx|address|tokens|search
  • SPV: gettxoutproof/verifytxoutproof partial-merkle proofs
  • P2P: full Bitcoin message set (24 handlers)

11. Use Cases

The same use cases that made Bitcoin matter — plus Alpha's token layer:

Digital Gold

Fixed 21M supply + halvings — a scarce, provably-limited store of value. Like Bitcoin, but on Alpha.

Peer-to-Peer Cash

Send value anywhere, no bank, no permission — final settlement in ~10-minute blocks.

Borderless Payments

Cross-border transfers without intermediaries, weekends, or cut-off times.

No Chargebacks

Confirmed transactions are final — merchants get fraud-proof settlement.

Censorship Resistance

No one can freeze or reverse your coins — you hold the keys, you own the coins.

Micropayments

Send fractions of a cent — divisible to 0.00000001 ALPHA (1 alphasat).

Programmable Money

Tokenization

Trustless cross-chain exchange with Bitcoin-family chains via HTLCs.
